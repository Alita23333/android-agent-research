# Independent local provider: measured storage increment and remaining admission boundary

Date: 2026-10-18. This document records existing source facts and implementation order; it does
not define another policy matrix, journal schema, hard-confirm system, registry or carrier.

## Existing route and limits

ZCode Core → production MCP carrier → bridge Gateway/CarrierAuthorization → Kotlin carrier worker
→ AndroidToolDispatcher → existing ToolRegistry → JsonRpcStdioProvider → app-UID child process.
ZCode Protocol and Android Local Tool Protocol JSON-RPC 2.0 remain separate.

The fixed `text_digest.inspect` route already supports real model calls, invalid-input recovery,
exact admitted operation result recording, a host-verified SHA-256 result and host-created artifact.
The device-info provider remains a fixed APK-owned shell provider. Neither example establishes
arbitrary imported-code execution admission or generic independent-provider installation acceptance.

## Storage increment implemented now

Only LocalProviderCatalog and JsonRpcStdioProvider production code changed. The existing v2
framed content hash and `tool-providers/<id>/versions/<hash>` layout are retained. The historical
`active` pointer selects stored candidate bytes; it is NOT a production execution grant.

Archive import now rejects traversals, ambiguous separators, exact/case/parent-component conflicts,
discarded siblings, invalid manifests, excessive message/archive metadata and built-in namespace
replacement. Versions are copied and checked before atomic publication; pointer replacement uses
sync + atomic move. Discovery/load verify physical paths and immutable hash. A descriptor cannot
substitute a command/directory for the verified stored version. Every child spawn, including crash
recovery, rechecks the original version pin. Spawn verification failure is non-retryable
`PROVIDER_INTEGRITY_FAILED` for an existing remote tool. Versions survive updates; no installer,
hook, tool negotiation or script executes during import. Physical links and non-regular files
are refused. These checks are integrity controls, not an isolation sandbox or atomic protection
against arbitrary concurrent code already running as the same UID.

## Next implementation sequence

1. Finish independent Android15 storage compatibility from the exact source/test package. Codex
   retains Android17 product acceptance; avoid repeating prior Skill GUI tests without a change.
2. Resolve explicit byte-bound host admission and non-executing definition discovery for imported
   providers against the current Gateway ceiling. A provider's arbitrary app-UID code can access
   app-owned state: a metadata label cannot make it read-only. Keep arbitrary execution unavailable
   while this boundary is unresolved; use existing trusted fixed-provider route as the regression.
3. Implement registration/schema/result/artifact/lifecycle mapping at existing boundaries, then
   prove an independently added tool with a real model task, exact Gateway record and physical
   artifact. Add failure/collision/cancel/restart checks for that increment.

Current status is **storage hardening + fixed-provider regression**, not completion of the
original generic provider extensibility criterion. Root, Shizuku, PTY, Linux and arbitrary script
execution remain outside this increment. No architecture assignment is delegated to ZCode.
